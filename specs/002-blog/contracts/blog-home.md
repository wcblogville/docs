# Contract: 블로그 홈·글 주소·검색 (화면 라우트)

**Feature**: `002-blog` | **Spec**: [../spec.md](../spec.md) | **Data model**: [../data-model.md](../data-model.md)

이 기능이 바깥에 보이는 화면 주소와, 주소마다 누가 무엇을 보는지·언제 다른 곳으로 보내는지를 정한다. 화면 문구는 spec 그대로이고, spec에 없어 plan이 임시로 정한 문구는 *(plan 임시)*로 표시했다 (팀 확인 대상, [plan.md](../plan.md) 남은 문제).

## 0. 공통

| 항목 | 약속 |
|---|---|
| 주소 형식 | 사용자에게 보이는 주소는 `/@{주소}`, `/@{주소}/{글ID}`. `next.config.ts` rewrites가 실제 페이지 `/blog/[slug]`, `/blog/[slug]/[postId]`로 잇고 주소창은 그대로 남는다 (FR-008). `/blog/{주소}`로 들어오는 길은 사이트 안 링크로 쓰지 않는다 |
| 주소 비교 | 들어온 주소를 그대로 DB 값과 비교한다. 대문자가 섞이면 404 (`/@Notice`) |
| 404 화면 | 🧭 `길을 잃었어요` / `찾는 블로그나 글이 없거나, 비공개 글이에요.` / [광장으로 돌아가기] → `/town` (FR-012, `src/app/not-found.tsx`). HTTP 404. 서버 오류(500)는 어떤 주소 값으로도 나지 않는다 (SC-009) |
| 숫자 값 | 글 ID·카테고리·소분류·페이지는 `parseId()`(1~2147483647, 숫자만, 앞자리 0·지수 표기 거부) |
| 탭 제목 | 루트 레이아웃 템플릿 `%s \| Blogville` |
| 보는 사람 구분 | 서버가 세션으로 정한다: **주인**(`viewer.userId === blogs.owner_id`), **다른 회원**, **방문자**(로그인 안 함). 화면에서 숨기는 것은 편의이고 판정은 서버다 (FR-060) |
| 반응형 | 375px에서 가로 스크롤 0, 버튼 글자 한 줄, 버튼·링크 누르는 영역 44×44px 이상 (FR-059, SC-004) |

## 1. `GET /@{주소}` — 블로그 홈

- 실제 파일: `src/app/blog/[slug]/page.tsx` (Server Component). 접근: 누구나 (로그인 불필요).
- 404: 주소에 맞는 블로그가 없음 (대문자 포함).
- 탭 제목: `{블로그 이름} | Blogville`. 없는 블로그는 `블로그를 찾을 수 없어요 | Blogville` (FR-015).

### 1.1 쿼리 값

| 값 | 형식 | 처리 | 잘못된 값 |
|---|---|---|---|
| `category` | 대분류 ID | 그 대분류 글(소분류 글 포함) | 정수가 아니면 무시 → 전체 글. 없는 번호·다른 블로그 번호 → 빈 목록, 제목 `전체 글 0개`, 선택 표시 없음 |
| `sub` | 소분류 ID | 그 소분류 글만 (`category`보다 먼저) | 정수가 아니면 무시 → `category` 또는 전체. 없는 번호·다른 블로그 번호 → 위와 같음 |
| `page` | 1 이상 | 8개씩 | 정수가 아니면 1페이지. 마지막보다 크면 빈 목록 + `🌱 아직 글이 없어요.` |
| `q` | 검색어 | **주인일 때만** 검색 모드 (1.4) | 주인이 아니면 무시 (보통 블로그 홈). 앞뒤 공백 제거 후 51자 이상이면 무시 |

페이지 링크는 고른 `category`/`sub`를 유지하고, 검색 모드의 페이지 링크는 `q`를 유지한다 (FR-057). 카테고리 링크는 `q`와 `page`를 버린다 (누르면 검색을 벗어나 그 카테고리 1페이지, 1.4).

### 1.2 화면 구성 (위에서 아래)

1. 미니룸 — 주인 장착 배경 + 캐릭터(2초 주기로 튐) + **주인 닉네임** 배지 + 전시 동물(있을 때, 캐릭터 오른쪽). 높이 640px 미만 224px / 이상 256px, 아래쪽 2px 선만 (FR-023~026, FR-030). 그림을 못 찾으면 캐릭터 회색 몸통·배경 초원.
2. 블로그 정보 — 주인 프로필(프로필 사진 48px 원형, 없으면 캐릭터 얼굴 + 닉네임), 블로그 이름(누르면 `/@{주소}`), 소개(비면 줄 없음, 줄바꿈 없이 한 줄), `@{주소} · 글 N · 이웃 N · 오늘 방문 N · 어제 방문 N · 전체 방문 N`, 오른쪽에 보는 사람별 버튼 (1.3) (FR-028, FR-047, FR-054).
3. 도감 — 다 키운 동물 카드(그림·이름·다 키운 날짜). 없으면 `아직 다 키운 동물이 없어요` (FR-029). 제목 `🏅 동물 도감` *(plan 임시)*.
4. 왼쪽(768px 미만은 위) 220px 상자: (주인만) 검색창, 카테고리 트리 `전체 글 (N)` / `여행 (5)` / `└ 맛집 (3)` (FR-040). 고른 줄은 노란 배경 + 굵게. 글이 없는 카테고리도 `(0)`.
5. 글 목록 — 제목 `{카테고리 이름 또는 "전체 글"} N개`, 카드 8개, 페이지 번호 (FR-056). 글이 없으면 `🌱 아직 글이 없어요.` + (주인만) [첫 글 쓰기] → `/write` (FR-058).

### 1.3 보는 사람별 차이

| 항목 | 주인 | 다른 회원 | 방문자 |
|---|---|---|---|
| 정보 줄 오른쪽 버튼 | [✏️ 글쓰기] → `/write`, [🎨 꾸미기] → `/closet`, [⚙️ 관리] → `/settings/blog` | [+ 이웃 추가] / [✓ 이웃] (social의 `toggleFollow`) | 없음 |
| 비공개 글 | 목록·카테고리 글 수에 포함, 카드에 `🔒 비공개` | 없음 | 없음 |
| `전체 글 (N)`, 정보 줄 `글 N` | 공개 글 수 | 공개 글 수 | 공개 글 수 |
| 검색창 | 있음 | 없음 | 없음 |
| 도감 카드의 전시 버튼 | [전시하기] / `전시 중` + [전시 빼기] *(plan 임시)* | 없음 | 없음 |
| 미니룸·프로필·전시 동물·도감 카드 | 같음 | 같음 | 같음 (US4-10) |
| 방문 기록 | 하지 않음 | 화면이 열리면 `recordBlogVisit` | 화면이 열리면 `recordBlogVisit` |

### 1.4 검색 모드 (`?q=`, 주인만)

- 검색창: 입력칸(`maxLength=50`, `aria-label="검색어"`, 안내 `마을의 글·블로그 검색` *(plan 임시)*) + [검색] *(plan 임시)*. GET으로 `/@{내 주소}?q={검색어}`.
- 검색어 앞뒤 공백 제거 후 비어 있으면: 목록 자리에 `검색어를 적어 주세요` (FR-053).
- 결과 (FR-051·052):
  - 제목 `🔍 '{검색어}' 검색 결과` *(plan 임시)*.
  - 1페이지에만 블로그 묶음 `블로그` *(plan 임시)*: 블로그 이름이나 주인 닉네임에 검색어가 든 블로그 최대 8곳, 최근 공개 글 순. 줄: 캐릭터 얼굴(또는 프로필 사진) · `{닉네임} · {블로그 이름}` · `@{주소}`, 누르면 `/@{주소}`.
  - 글 묶음 `글 N개` *(plan 임시)*: 마을 전체 **공개 글** 중 제목이나 본문에 검색어가 든 글, 최신순 8개씩, 마을 소식과 같은 카드(윗줄 `{닉네임} · {블로그 이름}`). 내 비공개 글도 넣지 않는다.
  - 둘 다 없으면 `검색 결과가 없어요`.
- 검색어의 `%`, `_`, `\`는 그 글자 그대로 찾는다.
- 검색 모드에서는 왼쪽 카테고리 트리에 선택 표시가 없고, 카테고리를 누르면 검색을 벗어난다.
- 응답: 결과 첫 페이지 1초 안 (SC-011).

### 1.5 방문 기록

- 주인이 아닌 사람이 화면을 열면 브라우저에서 `recordBlogVisit(blogId)`(Server Action, [profile-showcase.md](profile-showcase.md) 3절)를 한 번 부르고, 돌려받은 숫자로 `오늘 방문 N · 어제 방문 N · 전체 방문 N`을 바꾼다. 실패하면 처음 숫자 그대로, 문구 없음 (FR-043~049, 바뀌지 않음).

## 2. `GET /@{주소}/{글ID}` — 글 상세 (이 영역이 정하는 부분)

글 본문·댓글·공감은 post·social 계약이다. blog가 정하는 것은 다음뿐이다.

| 항목 | 약속 |
|---|---|
| 404 | 블로그 없음, 대문자 주소, 글 ID 형식 오류·범위 밖(`abc`, `0`, `012`, `1e1`, `2147483648`), 다른 블로그의 글, 남의 비공개 글 — 모두 같은 404 (FR-011·012) |
| 탭 제목 | `{글 제목} \| Blogville`, 비공개 글·없는 글은 `글 \| Blogville` (FR-015) |
| 블로그 링크 | 글 위 `{캐릭터 얼굴} {블로그 이름} · {닉네임}` → `/@{주소}`. 미니룸 없음 (FR-020·032) |
| 방문 기록 | 주인이 아니면 그 블로그 방문자로 센다 (블로그 홈과 합쳐 하루 1번, FR-043) |

## 3. `GET /settings/blog` — 블로그 관리

- 실제 파일: `src/app/settings/blog/page.tsx`. 접근: 회원 (`requireMember()`). 로그인하지 않았으면 `/`로 보낸다 (307, FR-022).
- 탭 제목 `블로그 관리 | Blogville`, 화면 제목 `⚙️ 블로그 관리`, 오른쪽 위 `내 블로그로 →` → `/@{지금 주소}` (FR-007).
- 카드 순서:
  1. `방문자`: `오늘 N · 어제 N · 전체 N`, 최근 7일 막대(0으로 채움, 마지막 `오늘` 노란 막대·굵게, 아래 날짜 `10/5`), 안내 `같은 사람은 하루 1번만 셉니다. 블로그 홈이나 글을 연 사람이 방문자이고, 내 방문은 세지 않아요.` (FR-048, 바뀌지 않음)
  2. `기본 정보`: 이름·소개 폼([저장], 소개 안내 `어떤 이야기를 쓰는 블로그인가요?`) + 주소 폼(라벨 `블로그 주소` *(plan 임시)*, `/@` + 칸, [주소 바꾸기] *(plan 임시)*). 지금의 `(주소는 바꿀 수 없어요)` 줄은 없앤다.
  3. `카테고리`: 대분류 줄(▲▼ · 이름 · (글 수) · [이름 바꾸기] [삭제]) 아래 들여 쓴 소분류 줄(같은 모양) + 대분류마다 [소분류 추가], 맨 아래 `새 카테고리` 칸 + [추가] (FR-033~039). 글 수는 비공개 포함.
- 처리는 [blog-settings.md](blog-settings.md)의 Server Action.

## 4. `GET /settings/account` — 내 정보 (닉네임 칸만)

- 페이지·접근 규칙·나머지 칸(소셜 연동, 탈퇴)은 auth 계약이다. blog는 `닉네임` 칸 하나를 끼운다 (FR-019).
- 칸: 라벨 `닉네임`, 지금 닉네임이 채워진 입력칸(`maxLength=20`), [저장]. 결과 문구는 [저장] 왼쪽 한 줄 — 오류 빨간 글씨, 성공 초록 `저장했어요 ✓` *(plan 임시, 블로그 관리와 같은 모양)*.
- 처리는 [profile-showcase.md](profile-showcase.md)의 `updateNickname`.

## 5. Route Handler

- 이 기능은 새 Route Handler를 만들지 않는다.
- 프로필 사진은 post 소유 `GET /files/{key}`로 그린다. **요청 (post)**: `profiles.photo_key`가 가리키는 첨부는 누구에게나 200으로 내려준다 (비공개 글 첨부 보호와 별개).

## 6. 이 화면들에 없는 것 (spec 범위 밖)

- 블로그 만들기·블로그만 지우기 화면이나 버튼 (FR-005).
- 예전 주소에서 새 주소로의 자동 이동 (D3).
- 광장(`/town`)·마을 소식(`/feed`)·남의 블로그 홈·방문자 화면의 검색창 (FR-050, SC-013).
- 카테고리 없는 글만 모아 보는 항목, 블로그 왼쪽 태그·최근 댓글 상자.
