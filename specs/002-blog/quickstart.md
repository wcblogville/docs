# Quickstart: 블로그 (BLOG) 끝까지 동작 확인

**Feature**: `002-blog` | **Plan**: [plan.md](plan.md) | **Contracts**: [contracts/](contracts/) | **Data model**: [data-model.md](data-model.md)

이 기능이 spec의 수용 시나리오와 SC를 지키는지 확인하는 실행 순서다. 명령은 코드 저장소 루트에서 실행한다. 비밀값은 `.env.local`에만 있고 여기에 적지 않는다. 구현 코드는 [plan.md](plan.md)의 변경 단위와 tasks에서 다룬다.

## 0. 전제

| 전제 | 없으면 |
|---|---|
| auth 단계 1 merge: 가입이 블로그를 만들고 `e2e/helpers.mjs`의 `loginDev`가 온보딩 없이 동작 | 모든 e2e가 로그인에서 멈춘다 |
| auth: `/settings/account` 페이지(골격이라도), `profiles.photo_key` | 닉네임 칸·프로필 사진 확인을 건너뛴다 |
| post 단계 3: `posts.subcategory_id`, 글쓰기 대분류·소분류 두 칸 | `e2e/categories.mjs`의 글 수·거르기·US5-11 확인을 건너뛴다 (스크립트가 컬럼 유무를 보고 표시) |
| town 단계 11: `user_animals` UNIQUE(`user_id`, `id`) → blog B-M3 | `e2e/blog-showcase.mjs`의 전시 확인을 건너뛴다 |
| `.env.local`에 `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `ADMIN_USERNAME`, `ADMIN_PASSWORD` (이름만, 값은 `.env.example` 참고) | 서버·관리자 계정을 만들 수 없다 |
| PostgreSQL 15 이상 (README 안내 17), Node.js 20.9 이상, 의존성 설치(`npm ci`) | B-M3(`ON DELETE SET NULL (컬럼)`)가 실패한다 |

## 2. DB와 서버 준비

먼저 **마이그레이션 전에** 개발 DB를 점검한다 (research R-28): 새 예약어와 같은 주소(관리자 `notice` 제외), 다른 회원 아이디와 같은 주소, 다른 회원 아이디와 대소문자 무시로 같은 닉네임, 160자 넘는 소개 — 모두 0건이어야 한다. `npm run db:studio`나 `psql`로 본다. 0건이 아니면 PR에 목록을 적는다 (160자 넘는 소개가 있으면 B-M2가 실패하므로 그 행을 먼저 고친다).

```bash
npm run db:migrate                       # B-M1 소분류, B-M2 블로그 작은 변경, (선행 뒤) B-M3 전시
npm run dev                              # 다른 터미널, http://localhost:3000
npm run db:seed && npm run db:reset && npm run admin:create
```

- 적용 뒤 `psql`의 `\d subcategories`, `\d blogs`로 제약 이름과 `ON DELETE SET NULL (showcase_animal_id)`를 확인한다.

### 3.1 `e2e/blog-home.mjs` 기대 결과

- 새 아이디로 가입 → DB에 그 회원 블로그가 정확히 1개, `slug` = 아이디, `title` = `{아이디}의 블로그`, 소개 `''`, 배경 초원, 대분류 "일상" 1개. 광장으로 이동한다 (US1-1·8, SC-001).
- 광장의 내 집 입구와 블로그 관리 `내 블로그로 →`가 `/@{아이디}`를 가리킨다 (US1-2, FR-007).
- 같은 회원 블로그를 DB에 하나 더 넣으면 `blogs_owner_id_unique`가 거부한다. 동시 두 요청도 1개 (US1-4).
- 블로그 홈·관리·꾸미기 어디에도 블로그 만들기·지우기 버튼이 없다 (US1-5).
- `npm run admin:create`를 두 번 실행해도 관리자 블로그 `/@notice`(이름 `Blogville 공지사항`, 소개 `마을 소식과 업데이트를 알려드려요`, 대분류 "공지")가 1개 (US1-6).
- 아이디 `town`, `notice`, `Admin`으로 가입 → `이 아이디는 쓸 수 없어요`, 회원·블로그 0 (US1-7, SC-012; 가입 처리는 auth).
- 방문자·다른 회원·주인 세 컨텍스트로 같은 블로그: 버튼 구성(없음 / 이웃 / 글쓰기·꾸미기·관리), 비공개 글은 주인에게만 `🔒 비공개` 배지·카테고리 글 수 포함, 탭 제목 `{블로그 이름} | Blogville` (US2-1·3·4).
- `/@Notice`, 없는 주소, 다른 블로그 글 ID, 남의 비공개 글, `abc`·`0`·`012`·`1e1`·`2147483648` → HTTP 404, `길을 잃었어요` (US2-2).
- 대분류 글 9개 이상인 블로그에서 대분류 선택 → 노란 배경, 2페이지에서도 유지 (US2-6).
- 글 없는 블로그: `🌱 아직 글이 없어요.`, [첫 글 쓰기]는 주인만 (US2-7).
- 375px: 가로 스크롤 0, 주인 버튼 3개 글자 한 줄(높이 44px 이상 ~ 두 줄 높이 미만), 주인 버튼·[첫 글 쓰기]·블로그 이름 링크·카테고리 링크 44×44px 이상 (US2-8, SC-004, FR-059, research R-24).
- `?category=1.5`, `?category=Infinity`, `?page=99999999999999999999`, `?sub=abc` → 200, 전체 글 1페이지 (US2-9, SC-009).

### 3.2 `e2e/blog-address.mjs` 기대 결과

- 이름 `  새 이름  ` [저장] → 같은 화면, `저장했어요 ✓`, DB `새 이름`, 블로그 홈 제목·탭 제목·광장 내 집 아랫줄·글 카드 블로그 이름이 바뀜. 설정 화면 열기부터 저장 완료까지 60초 안 (US3-1, SC-005·006).
- 공백만 / 41자 / 소개 161자 → 각각 `블로그 이름을 적어 주세요` / `블로그 이름은 40자까지예요` / `소개는 160자까지예요` 하나만, DB 그대로, **칸에 보낸 값이 남음** (US3-2).
- 소개 비움 → 블로그 홈에 소개 줄 없음 (US3-3).
- 주소 `My_Blog` → DB `my_blog`, `/@my_blog` 200, 예전 `/@{아이디}` 404, 블로그 홈·글 카드·광장·관리·발행 뒤 이동 주소가 모두 새 주소, 사이트가 그린 링크에 예전 주소 0개 (US3-4, SC-005).
- 주소 `ab` / `town` / 다른 회원의 주소 / 다른 회원의 아이디 → `주소는 영문 소문자, 숫자, _ 로 3~20자예요` / `이 주소는 쓸 수 없어요` / `이미 있는 주소예요` / `이미 있는 주소예요`, 주소 그대로 (US3-5, US3-9, SC-012).
- 아이디 `A`인 회원이 주소를 바꾼 뒤 다른 회원이 `A`로 바꾸려 하면 거부, `A` 본인은 `A`로 되돌릴 수 있다 (US3-9).
- 아이디가 아닌 주소 `x`를 `y`로 바꾼 직후 다른 회원이 `x`로 바꾸면 성공, `/@x`는 그 회원 블로그 (US3-10).
- 주소를 연달아 5번 바꿔도 매번 성공 (US3-11).
- 내 정보 닉네임: 정상 변경 → 미니룸 배지·글 상세·글 카드·광장 이름표 반영. `가` / 21자 / 다른 회원 닉네임 / 다른 회원 아이디의 대문자(`Tester2`) → `닉네임은 2자 이상이에요` / `닉네임은 20자까지예요` / `이미 있는 닉네임이에요` / `이미 있는 닉네임이에요`. `😀` 하나 → 500 없이 `닉네임은 2자 이상이에요` (US3-6, SC-012).
- 같은 값으로 가입과 주소 변경을 동시에 보내면 정확히 한쪽만 성공 (auth Edge Cases, SC-012).
- 이름·소개 저장 요청에 다른 칸(`slug`, `ownerId`)을 섞어 다시 보내기 → 내 블로그 이름·소개만 바뀜. 주소 처리에 남의 값을 섞어도 내 블로그만 (US3-7, SC-008).
- 로그아웃 상태 `/settings/blog` → `/`로 이동 (US3-8).

### 3.3 `e2e/categories.mjs` 기대 결과

- 대분류 추가(버튼·Enter) → 맨 아래, 칸 비움. "여행" 아래 [소분류 추가] "맛집" → 그 아래 맨 끝. 대분류 하나 + 소분류 하나를 누름 4번 이하로 (US5-1·2, SC-007).
- 같은 이름 대분류 추가·이름 바꾸기 → `이미 있는 카테고리예요`, 오류 때 추가 칸에 입력값 남음 (US5-3).
- "여행" 아래 "맛집" 또 → 거부, "공부" 아래 "맛집" → 성공 (US5-4).
- 공백만 / 21자 → `카테고리 이름을 적어 주세요` / `카테고리 이름은 20자까지예요` 그 칸 아래 한 줄, `  여행  ` → `여행` (US5-5).
- ▲▼: 블로그 홈 왼쪽·글쓰기 선택이 같은 순서, 맨 위 ▲·맨 아래 ▼ 비활성, 소분류는 같은 대분류 안에서만, DB `position` 0부터 빈틈 없음, 두 탭에서 추가와 순서 바꾸기를 동시에 해도 겹침 없음 (US5-6, FR-039).
- 블로그 홈 왼쪽 `여행 (5)` / `└ 맛집 (3)`, "여행" → 5개, "맛집" → 3개 (US5-7) *(post 단계 3 뒤)*.
- 소분류 "맛집" 삭제(확인 창 `'맛집' 소분류를 지울까요? 글은 '여행'에 남아요.`) → 글 3개가 `category_id` = 여행, `subcategory_id` NULL (US5-8) *(post 단계 3 뒤)*.
- 대분류 "여행" 삭제 확인 창 취소 → 그대로. 수락 → 대분류·소분류 삭제, 글은 두 칸 NULL, 글 `updated_at` 그대로, 서버 오류 없음 (US5-9, research R-11).
- 소분류 글이 있는 전용 회원을 DB에서 지우기(`DELETE FROM users WHERE id = …`) → 오류 없이 블로그·대분류·소분류·글이 함께 지워진다 (FR-005, research R-11, post 트리거 `posts_clear_subcategory`) *(post 단계 3 뒤)*.
- 다른 블로그 ID·`99999999999`·`abc`로 이름 바꾸기 → `잘못된 요청이에요`, 삭제·순서·소분류 추가 → 문구 없이 변화 없음, 500 없음 (US5-10, SC-008·009).
- 글쓰기: 대분류를 고르면 그 소분류만, 소분류 비워도 발행. 다른 대분류의 소분류를 섞은 요청 → 저장 안 됨 (US5-11, post 글쓰기 + DB 복합 FK) *(post 단계 3 뒤)*.

### 3.4 `e2e/blog-search.mjs` 기대 결과

실행마다 고유한 검색어(예: `맛집{실행 번호}`)로 글을 DB에 준비한다.

- 주인이 내 블로그 홈 검색창에 검색어 → 마을 전체 공개 글 중 제목·본문에 든 글만, 최신순 카드 8개, 2페이지 이동, 카드 윗줄 `{닉네임} · {블로그 이름}` (US6-1).
- 블로그 이름·닉네임에 검색어가 든 블로그가 블로그 묶음에 보이고 누르면 그 블로그 홈 (US6-2).
- 다른 회원의 비공개 글과 내 비공개 글에 검색어가 있어도 결과에 없다 (US6-3, FR-051, SC-008).
- 없는 검색어 → `검색 결과가 없어요`, 공백만 → `검색어를 적어 주세요` (US6-4, FR-053).
- 검색어 `%`, `_` → 그 글자가 든 글만 (모든 글이 나오지 않음).
- `/town`(데스크톱·휴대폰), `/feed`에 검색창 없음 (US6-5, SC-013).
- 방문자가 블로그 홈 → 검색창 없음. 방문자가 `/@{주소}?q=검색어` → 보통 블로그 홈, 결과 없음 (US6-6, SC-013).
- 회원이 남의 블로그 홈 → 검색창 없음, 자기 블로그 홈 → 있음 (US6-7, SC-013).
- 375px 검색 결과 화면 가로 스크롤 0 (SC-004).

### 3.5 `e2e/blog-showcase.mjs` 기대 결과

새 회원을 만들고 DB로 다 키운 동물 3마리와 알 1개를 넣는다.

- 방문자: 미니룸에 장착 배경·캐릭터·**닉네임** 배지(블로그 이름 아님), 캐릭터 애니메이션 주기 2초(계산된 스타일) (US4-1, FR-023·025).
- 꾸미기에서 배경 변경 → 블로그 홈 미니룸 배경이 바뀜 (US4-2).
- 장착 아이템의 그림 키를 없는 값으로(테스트 아이템을 DB에 넣어 장착) → 오류 문구·콘솔 오류 없이 회색 몸통·초원 (US4-3).
- 폭 375px 미니룸 높이 224px, 1280px 256px, 아래쪽 테두리 2px·나머지 0 (US4-4).
- 그 회원으로 `/api/uploads`에 사진을 올리고 DB로 `photo_key` 연결 → 방문자에게 프로필 사진(`/files/키`) + 닉네임. 사진 없는 회원 → 캐릭터 얼굴 (US4-5, FR-028) *(auth `photo_key` 뒤)*.
- 도감 카드 3장 (알은 없음). 다 키운 동물 없는 회원 → `아직 다 키운 동물이 없어요` (US4-6).
- 주인이 [전시하기] → 미니룸에 그 동물, 다른 동물 → 바뀜(늘 1마리), [전시 빼기] → 빈 자리. 고르지 않은 회원 → 빈 자리 (US4-7·8).
- `setShowcaseAnimal`에 남의 동물 ID·알 ID·`99999999999`·`"abc"`를 넣어 다시 보내기 → DB `showcase_animal_id` 그대로 (US4-9, SC-008).
- 주인·다른 회원·방문자의 미니룸·프로필·전시 동물·도감 카드가 같다 (전시 버튼만 주인에게) (US4-10).
