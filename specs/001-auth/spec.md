> 원본: `docs/01-requirements.md` v1.18, 4.1 회원 / 인증 (AUTH-01~AUTH-09)과 관련 비기능 요구사항(NF-01·02·09·10·11·12·14·18·19·26).

> - 가입은 사이트 아이디로만 한다. 소셜 계정은 가입이 아니라 **연동**해서 로그인 수단으로만 쓴다 (AUTH-01, AUTH-05).
> - 온보딩 단계는 없다. **회원가입 때 프로필·블로그가 기본값으로 함께 생긴다** (AUTH-02, AUTH-03, AUTH-07). 회원당 블로그 1개 필수, 닉네임 2~20자.
> - 로그인 유지: 브라우저를 닫거나 **2시간** 쓰지 않으면 로그아웃, [로그인 상태 유지]를 고르면 **7일** (AUTH-09).
> - 관리자 계정의 회원 식별자도 일반 가입 회원과 같은 형식이다 (AUTH-08).

## Clarifications

### Session 2026-10-07

- Q: 가입 아이디로 기본 블로그 주소 `/@{아이디}`·닉네임을 만들 수 없을 때(아이디가 예약어와 같거나, 다른 회원이 그 값을 이미 씀) 어떻게 하나? → A: 겹치지 않게 미리 막는다. (1) 예약어(블로그 주소 예약어 통합 목록과 같은 목록, BLOG-02)와 같은 아이디는 가입에서 받지 않고 `이 아이디는 쓸 수 없어요`를 보여준다. (2) 블로그 주소·닉네임을 바꿀 때 다른 회원의 아이디와 같은 값(대소문자 무시)은 쓸 수 없다 (주소는 `이미 있는 주소예요`, 닉네임은 `이미 있는 닉네임이에요`). 그래서 가입 때 기본 주소·닉네임은 항상 만들 수 있고, 숫자 덧붙이기 같은 대체값은 없다. 관리자 블로그 주소 `notice`도 예약어 목록에 넣는다.
- Q: 탈퇴한 회원이 남의 글에 단 댓글·답글은 함께 지울까, "탈퇴한 회원" 표시로 내용을 남길까? → A: 함께 지운다. 다른 사람의 답글이 달린 댓글은 기존 댓글 삭제 규칙대로 내용 없이 `삭제된 댓글이에요` 자리만 남는다. "탈퇴한 회원" 표시로 내용을 남기지 않는다 (constitution VII 최소 정보).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 아이디로 회원가입하고 바로 마을 주민이 되기 (Priority: P1)

처음 온 방문자가 첫 화면에서 아이디·비밀번호·비밀번호 확인을 적고 기본 캐릭터(남자 주민 / 여자 주민) 하나를 고른 뒤 가입한다. 가입이 끝나면 따로 로그인하거나 추가 정보를 입력하지 않아도 로그인 상태가 되고, 닉네임(= 아이디)과 블로그(`{아이디}의 블로그`, 주소 `/@{아이디}`)가 이미 만들어진 채로 광장에 도착한다. 닉네임·블로그 이름·주소는 나중에 바꾼다.

**Why this priority**: 가입하지 못하면 글쓰기·꾸미기·게임 보상 등 서비스의 모든 회원 기능을 쓸 수 없다. 원본 우선순위 M(AUTH-07, AUTH-02, AUTH-03)이며, "가입했지만 블로그가 없는 회원"이 없다는 규칙의 출발점이다.

**Independent Test**: 로그인하지 않은 상태에서 첫 화면 [회원가입] 탭으로 가입하고, 광장 도착·헤더의 레벨·코인·캐릭터 표시·`/@{아이디}` 블로그 존재·코인 100 지급을 확인하면 단독으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 로그인하지 않은 방문자가 첫 화면에 있다, **When** [회원가입] 탭에서 올바른 아이디·비밀번호·비밀번호 확인을 적고 캐릭터를 고른 뒤 [회원가입]을 누른다, **Then** 별도 로그인이나 추가 입력 없이 로그인 상태로 광장에 도착하고 환영 문구가 한 번 보인다.
2. **Given** 방문자가 아이디 `tester1`로 가입했다, **When** 가입 결과를 확인한다, **Then** 닉네임은 `tester1`, 블로그 이름은 `tester1의 블로그`, 블로그 주소는 `/@tester1`이고, 고른 캐릭터 1종과 기본 배경(초원)을 가지고 둘 다 장착되어 있으며, 가입 축하 코인 100이 지급되어 있다.
3. **Given** 방문자가 `Tester1`로 가입했다, **When** 다른 방문자가 `tester1` 또는 `TESTER1`로 가입하려 한다, **Then** 가입되지 않고 `이미 있는 아이디예요`가 보인다.
4. **Given** 방문자가 회원가입 칸에 있다, **When** 아이디를 영문 대문자·한글·특수문자로 적거나 3자 이하·21자 이상으로 적고 [회원가입]을 누른다, **Then** `아이디는 영문 소문자, 숫자, _ 로 4~20자예요`가 보인다 (대문자는 오류가 아니라 소문자로 바뀌어 저장된다).
5. **Given** 방문자가 회원가입 칸에 있다, **When** 비밀번호를 7자로 적는다, **Then** `비밀번호는 8자 이상이에요`가 보인다.
6. **Given** 방문자가 회원가입 칸에 있다, **When** 비밀번호와 비밀번호 확인을 다르게 적는다, **Then** `비밀번호가 서로 달라요`가 보인다.
7. **Given** 가입 중 오류가 났다, **When** 오류 문구가 보인다, **Then** 입력한 아이디와 고른 캐릭터는 지워지지 않고 남는다.
8. **Given** 가입 처리 중 회원·로그인 수단·프로필·블로그·기본 아이템·코인 지급 중 하나라도 실패한다, **When** 처리가 끝난다, **Then** 아무것도 저장되지 않고 회원은 생기지 않는다.
9. **Given** 누군가 가입 요청에 관리자 권한이나 기본 캐릭터가 아닌 아이템을 끼워 보낸다, **When** 가입이 처리된다, **Then** 권한은 일반 회원으로만 정해지고, 기본 캐릭터가 아닌 아이템은 거부된다.
10. **Given** 이미 로그인한 회원이, **When** 첫 화면에 들어온다, **Then** 광장으로 이동한다.
11. **Given** 방문자가 회원가입 칸에 있다, **When** 블로그 주소 예약어와 같은 아이디(예: `admin`, `settings`, `notice`, 대문자로 적은 `Admin` 포함)로 [회원가입]을 누른다, **Then** 가입되지 않고 `이 아이디는 쓸 수 없어요`가 보인다.
12. **Given** 회원 A가 블로그 주소를 `cooking`으로, 또는 닉네임을 `Cooking`으로 바꿔 쓰고 있다 (그때는 아이디 `cooking`인 회원이 없었다), **When** 다른 방문자가 아이디 `cooking`으로 가입하려 한다, **Then** 가입되지 않고 `이미 있는 아이디예요`가 보인다.
13. **Given** 회원가입이 받아들여졌다, **When** 가입 결과를 확인한다, **Then** 블로그 주소는 늘 `/@{아이디}`, 닉네임은 늘 `{아이디}` 그대로이고, 숫자를 덧붙인 주소 같은 대체값은 생기지 않는다.
14. **Given** 아이디 `tester1`인 회원이 있다, **When** 다른 회원이 블로그 주소를 `tester1`로, 또는 닉네임을 `Tester1`로 바꾸려 한다, **Then** 바뀌지 않고 각각 `이미 있는 주소예요` / `이미 있는 닉네임이에요`가 보인다. `tester1` 본인은 자기 주소·닉네임을 `tester1`로 되돌릴 수 있다.

### User Story 2 - 아이디로 로그인하고, 로그인 유지를 고르고, 로그아웃하기 (Priority: P1)

가입한 회원(관리자 포함)이 첫 화면 [로그인] 탭에서 아이디·비밀번호로 로그인한다. 기본으로는 브라우저를 닫거나 마지막 사용 후 2시간이 지나면 로그아웃되고, [로그인 상태 유지]를 고르면 7일 동안(쓰는 동안 연장) 유지된다. 헤더 오른쪽 끝 [로그아웃]으로 언제든 나갈 수 있다.

**Why this priority**: 가입 뒤 다시 들어오는 유일한 기본 수단이다 (AUTH-09, AUTH-04 모두 M). 로그인 실패 문구가 아이디 존재 여부를 드러내지 않는 것은 보안 기준이다.

**Independent Test**: 미리 만든 테스트 회원으로 로그인·잘못된 비밀번호·없는 아이디·로그인 상태 유지 선택/미선택·2시간 미사용·로그아웃을 차례로 시험하면 단독으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 가입한 회원이 첫 화면에 있다, **When** 맞는 아이디·비밀번호로 [로그인]을 누른다, **Then** 광장으로 이동하고 헤더에 레벨·코인·캐릭터가 보인다.
2. **Given** `tester1`로 가입한 회원이, **When** `TESTER1`로 로그인한다, **Then** 로그인된다 (아이디는 대소문자를 구분하지 않는다).
3. **Given** 첫 화면 [로그인] 탭, **When** 아이디나 비밀번호를 비워 두고 [로그인]을 누른다, **Then** `아이디와 비밀번호를 적어 주세요`가 보인다.
4. **Given** 첫 화면 [로그인] 탭, **When** 없는 아이디로 로그인하거나, 있는 아이디에 틀린 비밀번호로 로그인한다, **Then** 두 경우 모두 똑같이 `아이디 또는 비밀번호가 맞지 않아요`가 보인다.
5. **Given** 관리자가, **When** 로그인한다, **Then** 헤더에 [👑 관리자] 버튼이 보인다.
6. **Given** 회원이 [로그인 상태 유지]를 고르지 않고 로그인했다, **When** 브라우저를 완전히 닫았다가 다시 열거나, 브라우저를 켜 둔 채 마지막 사용 후 2시간이 지난다, **Then** 로그아웃된 상태이고 회원 화면에 들어가면 첫 화면으로 간다.
7. **Given** 회원이 [로그인 상태 유지]를 골라 로그인했다, **When** 브라우저를 닫았다가 다시 열거나 2시간 넘게 쓰지 않았다가 7일 안에 돌아온다, **Then** 로그인 상태가 유지되고, 쓰는 동안 유지 기간이 다시 7일로 연장된다.
8. **Given** 로그인한 회원이, **When** 헤더 오른쪽 끝 [로그아웃]을 누른다, **Then** 로그인 세션이 끝나고 첫 화면으로 이동하며, 헤더에 [시작하기] 버튼이 보이고, 회원 화면에 들어가면 첫 화면으로 간다.
9. **Given** 로그인 처리 중이다, **When** 화면을 본다, **Then** 버튼이 `들어가는 중...`으로 바뀌고 다시 누를 수 없다.

### User Story 3 - 연동해 둔 소셜 계정으로 로그인하기 (Priority: P1)

아이디로 가입한 뒤 카카오·네이버·구글 계정을 연동해 둔 회원이 첫 화면 `간편 로그인`의 [카카오] [네이버] [Google] 버튼으로 비밀번호 없이 로그인한다. 연동하지 않은 소셜 계정으로는 새 회원이 생기지 않고 연동 방법을 안내받는다.

**Why this priority**: 원본 우선순위 M (AUTH-01). 비밀번호를 잊어도 연동한 소셜 계정으로 들어올 수 있는 빠른 로그인 수단이다. 다만 실제 로그인은 연동(User Story 4)과 각 서비스의 연결 준비(키 발급)가 끝나야 가능하다.

**Independent Test**: (1) 연결 준비가 안 된 서비스 버튼의 비활성 표시, (2) 연동하지 않은 소셜 계정으로 로그인 시도 시 안내 문구와 회원 수 불변, (3) 미리 연동해 둔 테스트 회원의 소셜 로그인 성공을 확인하면 단독으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 카카오 계정을 연동해 둔 회원이 로그아웃 상태다, **When** 첫 화면 [카카오]를 누르고 카카오 로그인을 마친다, **Then** 연동한 그 회원으로 로그인되어 광장으로 이동한다.
2. **Given** 어떤 회원에도 연동되지 않은 소셜 계정이 있다, **When** 그 계정으로 [카카오]/[네이버]/[Google] 로그인을 마친다, **Then** 새 회원이 생기지 않고 첫 화면에 `연동된 계정이 없어요. 아이디로 로그인한 뒤 내 정보에서 연동해 주세요`가 보인다.
3. **Given** 어떤 서비스의 연결 준비가 되어 있지 않다, **When** 첫 화면을 본다, **Then** 그 서비스 버튼은 흐리게 비활성이고, 마우스를 올리면 `아직 연결 준비 중이에요`가 보인다.
4. **Given** 세 서비스 모두 연결 준비가 되어 있지 않다, **When** 첫 화면을 본다, **Then** 버튼 아래에 `간편 로그인은 준비 중이에요`가 보인다.
5. **Given** 첫 화면 `간편 로그인` 영역, **When** 화면을 본다, **Then** [카카오](노랑) [네이버](초록) [Google](흰색) 3칸 아래에 `처음이라면 회원가입 후 내 정보에서 연동해 주세요` 안내가 보인다.
6. **Given** 회원 A의 이메일과 같은 이메일을 쓰는 소셜 계정이 있지만 A에 연동되어 있지 않다, **When** 그 소셜 계정으로 로그인한다, **Then** 이메일이 같다는 이유로 A에 자동으로 붙거나 A로 로그인되지 않는다.

### User Story 4 - 내 정보에서 소셜 계정 연동·해제하기 (Priority: P2)

아이디로 가입한 회원이 내 정보 화면에서 서비스마다 연동 상태를 보고, [연동하기]로 카카오·네이버·구글 계정을 붙이거나 [연동 해제]로 떼어 낸다. 아이디 로그인은 항상 남는다.

**Why this priority**: 원본 우선순위 S (AUTH-05). 소셜 로그인(User Story 3)을 실제로 쓰게 해 주는 기능이지만, 아이디 로그인만으로도 서비스 전체를 쓸 수 있다.

**Independent Test**: 테스트 회원으로 로그인해 카카오 연동 → 로그아웃 → [카카오] 로그인 → 연동 해제 → [카카오] 로그인 실패·아이디 로그인 성공을 확인하면 단독으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원이, **When** 블로그 관리 화면이나 헤더 프로필에서 내 정보로 들어간다, **Then** 서비스마다 `연동됨 (연동한 날짜)` 또는 [연동하기]가 보인다.
2. **Given** 카카오를 연동하지 않은 회원이 내 정보에 있다, **When** [카카오 연동하기]를 누르고 카카오 로그인·동의를 마치고 돌아온다, **Then** `카카오 계정을 연동했어요`가 보이고, 로그아웃 뒤 첫 화면 [카카오]로 같은 회원에 로그인된다.
3. **Given** 어떤 카카오 계정이 이미 다른 회원에 연동되어 있다, **When** 그 카카오 계정으로 연동을 시도한다, **Then** 연동되지 않고 `이미 다른 Blogville 계정에 연동된 카카오 계정이에요`가 보인다.
4. **Given** 회원이 이미 카카오 계정 하나를 연동했다, **When** 다른 카카오 계정을 또 연동하려 한다, **Then** 버튼이 `연동됨`이라 누를 수 없고, 화면을 거치지 않고 요청을 조작해 보내도 거부된다 (서비스마다 1개).
5. **Given** 카카오를 연동한 회원이, **When** [연동 해제]를 누르고 확인한다, **Then** 그 카카오 연결만 지워져 [카카오]로는 로그인되지 않고, 아이디 로그인은 그대로 된다.
6. **Given** 내 정보 화면, **When** 아이디 로그인 항목을 본다, **Then** 해제 버튼이 없고, 요청을 조작해 아이디 로그인을 지우려 해도 거부된다.

### User Story 5 - 관리자가 통계·회원을 보고 아무 글이나 지우기 (Priority: P2)

운영자가 미리 만들어 둔 관리자 계정으로 로그인해 관리자 페이지에서 통계, 최근 가입 회원, 최근 글을 보고, 문제가 있는 글은 어느 블로그의 글이든 지운다. 일반 회원에게는 관리자 페이지가 있다는 사실조차 드러나지 않는다.

**Why this priority**: 원본 우선순위 S (AUTH-08). 운영에 필요하지만 일반 회원 경험의 핵심 흐름은 아니다.

**Independent Test**: 관리자 계정과 일반 회원 계정, 다른 회원의 글을 준비해 관리자 화면 표시·글 삭제·일반 회원 접근 차단을 확인하면 단독으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 관리자가 로그인했다, **When** 헤더의 [👑 관리자]를 누른다, **Then** 관리자 페이지에서 통계 카드, 최근 가입 회원(최신 20명), 최근 글(최근 30일, 최대 30개, 최신순)이 보인다.
2. **Given** 관리자가 최근 글 목록에 있다, **When** 남의 글의 [삭제]를 누르고 확인 창 `'{제목}' 글을 삭제할까요?`에서 확인한다, **Then** 그 글이 어느 블로그의 글이든 지워진다.
3. **Given** 일반 회원이나 로그인하지 않은 사람이, **When** 관리자 페이지 주소로 들어가거나 관리자 글 삭제 요청을 직접 보낸다, **Then** "페이지를 찾을 수 없음"(404)으로 응답하고 아무것도 지워지지 않으며, 헤더에 관리자 버튼도 보이지 않는다.
4. **Given** 운영자가 서버에만 둔 관리자 아이디·비밀번호 설정으로 관리자 계정 만들기를 실행한다, **When** 같은 작업을 여러 번 실행한다, **Then** 관리자 계정과 공지사항 블로그(`/@notice`)는 한 번만 생기고, 다시 실행하면 비밀번호만 갱신된다.
5. **Given** 예전 방식(다른 형식의 회원 식별자)으로 만든 관리자 계정이 있다, **When** 관리자 계정 만들기를 다시 실행한다, **Then** 기존 계정의 식별자는 바꾸지 않고, 새 형식으로 다시 만들어야 한다는 안내만 보여준다.

### User Story 6 - 같은 아이디로 반복 실패하면 잠시 로그인 막기 (Priority: P2)

누군가 한 아이디의 비밀번호를 계속 추측하면 잠시 그 아이디의 로그인을 막아 계정을 지킨다.

**Why this priority**: AUTH-09 수용 기준의 "보완 필요" 항목이자 NF-10(우선순위 S). 비밀번호 추측 공격을 막지만, 로그인 자체가 먼저 있어야 의미가 있다.

**Independent Test**: 테스트 회원 아이디로 5번 연속 틀린 뒤 6번째 시도, 5분 경과 후 시도, 성공 후 실패 횟수 초기화, 없는 아이디의 같은 동작을 확인하면 단독으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 한 아이디로 5번 연속 로그인에 실패했다, **When** 6번째로 로그인한다 (비밀번호가 맞아도), **Then** 로그인되지 않고 `로그인을 너무 많이 시도했어요. 5분 뒤에 다시 시도해 주세요`가 보인다.
2. **Given** 잠긴 아이디가 있다, **When** 5분이 지난 뒤 맞는 비밀번호로 로그인한다, **Then** 로그인된다.
3. **Given** 한 아이디로 3번 틀린 뒤, **When** 맞는 비밀번호로 로그인에 성공한다, **Then** 실패 횟수가 초기화되어 이후 다시 5번 틀려야 잠긴다.
4. **Given** 가입되지 않은 아이디가 있다, **When** 그 아이디로 5번 연속 실패한 뒤 6번째로 시도한다, **Then** 있는 아이디와 똑같이 잠금 문구가 보여, 어떤 아이디가 있는지 알 수 없다.

### User Story 7 - 회원 탈퇴하기 (Priority: P2)

회원이 더 이상 서비스를 쓰지 않을 때 스스로 탈퇴하면 개인정보와 글이 지워진다.

**Why this priority**: 원본 우선순위 S (AUTH-06), 상태 ⬜(화면·기능 없음). 개인정보를 최소로 다룬다는 원칙에 필요하지만 다른 흐름보다 덜 급하다.

**Independent Test**: 글·코인 내역·연동 계정과, 남의 글에 단 댓글·답글(다른 회원의 답글이 달린 댓글 포함)을 가진 테스트 회원으로 탈퇴한 뒤, 로그인 불가·블로그 주소 접근 불가·관련 데이터 삭제·댓글 자리 처리를 확인하면 단독으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원이 내 정보에 있다, **When** 탈퇴를 요청하고 비밀번호를 다시 입력해 확인한다, **Then** 회원·프로필·블로그·글·남의 글에 단 댓글과 답글·코인·경험치 기록·보유 아이템·연동한 소셜 계정 연결이 함께 지워지고, 로그아웃되어 첫 화면으로 간다.
2. **Given** 회원이 탈퇴했다, **When** 그 아이디나 그 회원에 연동했던 소셜 계정으로 로그인한다, **Then** 로그인되지 않는다 (아이디는 `아이디 또는 비밀번호가 맞지 않아요`, 소셜은 연동 없음 안내).
3. **Given** 회원이 탈퇴했다, **When** 다른 사람이 그 블로그 주소로 들어간다, **Then** 블로그를 찾을 수 없다.
4. **Given** 탈퇴 확인 단계에서, **When** 비밀번호를 틀리게 입력한다, **Then** 탈퇴되지 않고 아무것도 지워지지 않는다.
5. **Given** 탈퇴하는 회원이 남의 글에 답글 없는 댓글 1개와 다른 회원의 댓글에 단 답글 1개를 달아 두었다, **When** 탈퇴가 끝난다, **Then** 두 개 모두 자리 없이 지워져 그 글에서 보이지 않는다.
6. **Given** 탈퇴하는 회원이 남의 글에 단 댓글에 다른 회원의 답글 2개가 달려 있다, **When** 탈퇴가 끝난다, **Then** 그 댓글 자리에는 내용 없이 `삭제된 댓글이에요`만 남고(탈퇴로 프로필이 지워지므로 작성자 닉네임·캐릭터도 보이지 않는다), 다른 회원의 답글 2개는 그대로 보인다. "탈퇴한 회원" 같은 표시로 원래 내용을 남기지 않는다.

---

### Edge Cases

- 가입하려는 아이디가 블로그 주소 예약어(BLOG-02와 같은 목록, 예: `admin`, `town`, `settings`, `notice`)와 같으면 가입되지 않고 `이 아이디는 쓸 수 없어요`가 보인다. 다른 회원이 이미 블로그 주소나 닉네임으로 쓰는 값(대소문자 무시)과 같은 아이디는 `이미 있는 아이디예요`가 보인다. 그래서 가입이 받아들여지면 기본 주소 `/@{아이디}`·닉네임 `{아이디}`는 항상 만들 수 있고, 숫자를 덧붙인 주소 같은 대체값은 쓰지 않는다 (FR-010).
- 회원이 블로그 주소·닉네임을 다른 회원의 아이디와 같은 값(대소문자 무시)으로 바꾸려 하면 바뀌지 않는다 (`이미 있는 주소예요` / `이미 있는 닉네임이에요`). 자기 아이디와 같은 값은 그 회원만 쓸 수 있고, 언제든 그 값으로 되돌릴 수 있다 (FR-009).
- 한 방문자가 아이디 X로 가입하는 순간 다른 회원이 블로그 주소나 닉네임을 X로 바꾸면, 둘 중 한쪽만 성공하고 다른 쪽은 위 문구 중 해당하는 것을 본다. 아이디·주소·닉네임이 겹친 회원은 생기지 않는다.
- 두 사람이 같은 아이디로 거의 동시에 가입하면 한 사람만 가입되고 다른 사람은 `이미 있는 아이디예요`를 본다.
- 가입 중 일부 처리만 성공하고 나머지가 실패해도 반쪽짜리 회원(블로그나 프로필이 없는 회원)은 생기지 않는다.
- 비밀번호를 64자보다 길게 입력하려 하면 입력 칸이 더 받지 않고, 화면을 거치지 않고 보내도 거부된다.
- 아이디 앞뒤 공백이나 대문자를 섞어 로그인해도 같은 아이디로 취급한다 (대문자는 소문자로 바꿔 비교).
- [로그인 상태 유지] 없이 로그인한 회원이 브라우저 탭만 닫고 브라우저는 켜 둔 경우, 마지막 사용 후 2시간 안이면 로그인이 유지되고 2시간이 지나면 끝난다. 서버는 창이 닫힌 것을 알 수 없으므로 남은 세션도 2시간이 지나면 무효가 된다.
- 하루에 처음 로그인한 세션은 자동 출석(GAME-04)과 이어진다. 로그인 유지 시간이 바뀌어도 자동 출석 동작은 그대로다.
- 소셜 로그인·연동 도중 사용자가 소셜 서비스 화면에서 취소하거나 동의하지 않으면, 아무것도 바뀌지 않고 원래 화면(첫 화면 또는 내 정보)으로 돌아온다.
- 소셜 계정을 연동한 회원이 비밀번호를 잊어도 연동한 소셜 계정으로 로그인할 수 있다.
- 로그인한 사용자의 로그인 정보를 이용해 다른 사이트에서 보낸 요청(로그아웃, 연동 해제, 글 삭제 등)은 거부된다.
- 공지사항 블로그 주소 `notice`는 예약어 목록에 들어 있어, 관리자 계정 만들기를 하기 전에도 일반 회원이 아이디나 블로그 주소로 먼저 차지할 수 없다.
- 탈퇴 처리 중 일부가 실패하면 아무것도 지워지지 않는다.
- 탈퇴로 그 회원의 글이 지워지면서 거기 달린 다른 회원의 댓글·답글·공감이 함께 사라져도, 다른 회원이 이미 받은 경험치·코인은 회수하지 않는다 (글·댓글 삭제 때와 같은 기준, GAME-05).
- 탈퇴로 지워진 댓글에 다른 회원이 답글을 저장하려 하면 답글 규칙(SOC-02)대로 거부되고 입력한 내용은 남는다: 자리 없이 지워진 댓글이면 `답글을 달 댓글이 없어요`, `삭제된 댓글이에요` 자리만 남은 댓글이면 `삭제된 댓글에는 답글을 달 수 없어요`.
- 잠금 중인 아이디로 연동한 소셜 계정 로그인은 막지 않는다 (잠금은 아이디·비밀번호 로그인에만 적용).

## Requirements *(mandatory)*

### Functional Requirements

**회원가입 (AUTH-07, AUTH-02, AUTH-03)**

- **FR-001** (AUTH-07): 시스템은 로그인하지 않은 방문자가 첫 화면에서 아이디·비밀번호·비밀번호 확인과 기본 캐릭터 1종(남자 주민 / 여자 주민)을 골라 회원가입할 수 있게 해야 한다. 첫 화면 카드에는 [로그인] [회원가입] 탭이 있고 처음에는 [로그인] 탭이 열려 있다. 캐릭터는 처음에 남자 주민이 골라져 있다.
- **FR-002** (AUTH-07): 시스템은 아이디를 영문 소문자·숫자·`_` 4~20자로만 받아야 하며, 대문자로 입력하면 소문자로 바꿔 저장해야 한다. 아이디 칸 아래에 `영문 소문자, 숫자, _ 로 4~20자` 안내를 보여야 한다. 형식이 틀리면 `아이디는 영문 소문자, 숫자, _ 로 4~20자예요`를 보여야 한다.

- **FR-049** (AUTH-08): 시스템은 새로 만드는 관리자 계정의 회원 식별자를 일반 가입 회원과 같은 형식으로 만들어야 한다. 예전 형식으로 만든 관리자 계정은 식별자를 바꾸지 않고, 새 형식으로 다시 만들라는 안내만 보여야 한다.

**회원 탈퇴 (AUTH-06)**

- **FR-050** (AUTH-06): 시스템은 로그인한 회원이 내 정보에서 탈퇴를 요청하고 비밀번호를 다시 입력해 확인하면 탈퇴를 처리해야 한다. 비밀번호가 틀리면 탈퇴하지 않아야 한다.
- **FR-051** (AUTH-06): 시스템은 탈퇴하면 그 회원의 개인정보(아이디·로그인 수단·연동한 소셜 계정 연결·프로필), 블로그와 글, 남의 글에 단 댓글·답글(FR-052), 코인·경험치 기록, 보유 아이템, 그 회원이 받은 알림과 그 회원이 한 공감·댓글·답글로 다른 회원에게 남은 알림(GAME-08) 등 회원에 딸린 데이터를 함께 지우고, 하나라도 실패하면 전부 취소해야 한다. 탈퇴가 끝나면 로그아웃시키고 첫 화면으로 보내야 한다.
- **FR-052** (AUTH-06): 시스템은 탈퇴한 회원이 남의 글에 단 댓글·답글을 탈퇴 때 자리 없이 함께 지워야 한다. 다만 다른 회원의 답글이 달린 댓글은 기존 댓글 삭제 규칙(SOC-01)대로 내용 없이 `삭제된 댓글이에요` 자리만 남기고 다른 회원의 답글은 그대로 둔다. 이때 탈퇴로 프로필이 지워지므로, 작성자 닉네임·캐릭터를 보여 주는 일반 삭제 자리(SOC-01)와 달리 그 자리에 탈퇴한 회원의 닉네임·캐릭터는 보이지 않아야 한다. "탈퇴한 회원" 같은 표시로 지운 댓글·답글의 내용을 남기지 않아야 한다.

**공통 (NF)**

- **FR-054** (NF-06, NF-18): 첫 화면(로그인·회원가입), 내 정보, 관리자 페이지는 375px 너비와 PC에서 가로 스크롤 없이 쓸 수 있어야 하고, 버튼·링크의 누르는 영역은 최소 44×44px, 버튼 글자는 두 줄로 쪼개지지 않아야 한다. 로그인·회원가입은 키보드(Tab, Enter)만으로 할 수 있고 지금 선택된 곳이 눈에 보여야 한다.

### Key Entities *(include if feature involves data)*

- **회원**: 서비스를 쓰는 한 사람. 아이디(소문자, 유일. 회원가입에서는 블로그 주소 예약어와 같은 아이디나 다른 회원의 블로그 주소·닉네임과 같은 아이디를 받지 않음, FR-010), 권한(일반 회원 / 관리자), 가입 시각을 가진다. 모든 회원은 아이디·비밀번호 로그인 수단을 반드시 하나 가진다.
- **로그인 수단**: 회원이 들어오는 방법. 아이디·비밀번호(비밀번호는 해시) 1개와, 서비스(카카오·네이버·구글)마다 최대 1개의 연동한 소셜 계정(서비스 쪽 계정 식별자, 연동한 날짜). 한 소셜 계정은 한 회원에만 연결된다.
- **로그인 세션**: 로그인한 상태. 만든 시각, 마지막 사용 시각, 만료 시각, [로그인 상태 유지] 여부를 가진다. 기본은 마지막 사용 후 2시간, 유지를 고르면 7일 뒤 만료된다. 그날 처음 만든 세션이 자동 출석(GAME-04)과 이어진다.
- **로그인 실패 기록**: 아이디별 연속 실패 횟수와 잠금 해제 시각. 성공하면 초기화된다. 가입되지 않은 아이디에도 생길 수 있다.
- **프로필**: 회원 1명당 정확히 1개. 닉네임(2~20자, 유일, 다른 회원의 아이디와 같을 수 없음(대소문자 무시), 기본값 = 아이디), 장착한 캐릭터, (선택) 프로필 사진.
- **블로그**: 회원 1명당 정확히 1개. 이름(기본값 `{아이디}의 블로그`), 주소(유일, 예약어 불가, 다른 회원의 아이디와 같을 수 없음, 기본값 = 아이디), 소개(처음엔 빈 값), 장착한 배경. 가입 때 기본 카테고리 "일상"과 함께 생긴다.
- **가입 지급**: 가입 때 고른 기본 캐릭터 1종, 기본 배경(초원), 가입 축하 코인 100(코인 원장 항목 1건).
- **관리자 계정**: 권한이 관리자인 회원. 운영자 설정으로만 만들어지며 공지사항 블로그(`/@notice`)를 가진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 온 방문자가 첫 화면에서 회원가입을 시작해 광장에 도착하기까지 1분 이내, 입력 칸은 4개 이하(아이디·비밀번호·비밀번호 확인·캐릭터 선택)다.

- **SC-005**: [로그인 상태 유지] 없이 로그인한 세션은 마지막 사용 후 2시간이 지나면 100% 로그아웃 상태이고, 유지를 고른 세션은 7일 안에 돌아오면 다시 로그인하지 않아도 된다.
- **SC-006**: 같은 아이디로 5번 연속 실패하면 6번째 시도부터 5분 동안 로그인이 100% 거부된다.
- **SC-007**: 연동하지 않은 소셜 계정으로 로그인을 시도해도 새로 생기는 회원은 0명이다.

- **SC-012**: 소셜 계정을 연동한 회원은 로그아웃 뒤 소셜 버튼 한 번과 소셜 서비스 로그인만으로(비밀번호 입력 없이) 같은 회원으로 로그인된다.
- **SC-013**: 회원가입으로 생긴 회원 중 블로그 주소 예약어와 같은 아이디를 가진 회원, 가입 직후 블로그 주소가 `/@{아이디}`가 아니거나 닉네임이 아이디가 아닌 회원은 항상 0명이다. 블로그 주소나 닉네임이 다른 회원의 아이디와 같은(대소문자 무시) 회원도 항상 0명이다.

- 기본값 (원본 열린 질문, AUTH-06): 실수로 탈퇴하는 것을 막기 위해 비밀번호를 다시 입력받는다. 유예 기간(예: 7일) 없이 즉시 지운다.
- 기본값 (원본에 없음, AUTH-06): 탈퇴한 아이디는 데이터가 모두 지워지므로 다시 가입할 수 있다 (그 사이 다른 회원이 그 값을 블로그 주소나 닉네임으로 쓰기 시작했다면 FR-010에 따라 `이미 있는 아이디예요`). 탈퇴 회원에 연동했던 소셜 계정도 다른 회원에 다시 연동할 수 있다.
- 기본값 (원본에 없음, AUTH-05): 연동 해제 확인 문구는 `카카오 연동을 해제할까요? 아이디 로그인은 그대로 쓸 수 있어요`처럼 서비스 이름을 넣어 보여준다. 연동 성공·중복 문구도 원본의 카카오 예시를 서비스 이름만 바꿔 네이버·구글에 쓴다.
- 기본값 (원본에 없음, AUTH-07): 비밀번호 64자 초과는 입력 칸이 더 받지 않으므로 별도 화면 문구를 두지 않는다. 화면을 거치지 않은 요청은 거부한다.
- 기본값 (원본 열린 질문, AUTH-01): 소셜 서비스 키를 누구 계정으로 발급할지는 운영 결정이며 이 spec의 동작에는 영향이 없다. 키가 없는 동안은 FR-031의 비활성 표시를 따른다.

**범위 밖 (Out of Scope)**

- 소셜 계정으로 새로 가입하기 (2026-10-07 결정으로 제외, 연동으로 대체).
- 온보딩 화면 (2026-10-07 결정으로 없어짐).
- 이메일 수집·이메일 인증·비밀번호 찾기 (위 기본값 참고).
- 닉네임·블로그 이름·블로그 주소 변경 화면 자체 (BLOG-03, 내 정보의 닉네임·프로필 사진 편집은 별도 spec). 이 spec은 내 정보의 소셜 연동·탈퇴 부분만 다룬다. 다만 "다른 회원의 아이디와 같은 주소·닉네임 금지"(FR-009)는 그 변경 화면들에 그대로 적용된다.
- 자동 출석과 출석 보상 (GAME-04), 기본 캐릭터 상세 규칙 (GAME-01), 광장 환영 문구 표시 규칙 (TOWN-01) — 이 spec은 가입·로그인과 이어지는 지점만 다룬다.
- 친구 초대 보상 (GAME-09, 2026-10-07 보류).
- 관리자 페이지의 회원 정지·아이템 지급, 여러 관리자 화면 관리. (관리자의 댓글·답글 삭제는 SOC-01·SOC-02에서 다룬다.)
- 접속 위치(IP) 기준 로그인 제한, 2단계 인증.

**의존성**

- 소셜 로그인·연동(AUTH-01, AUTH-05)은 각 서비스 개발자 센터의 키 발급과 배포 주소 확정이 있어야 실제로 켜진다.
- 가입 지급은 기본 캐릭터(남자 주민·여자 주민)와 기본 배경(초원) 아이템, 코인 원장(GAME 영역)이 있어야 한다.
- 관리자 통계의 "오늘 출석"은 출석 기록(GAME-04)에 의존한다.
- 아이디 예약어는 블로그 주소 예약어 목록(BLOG-02)에, 탈퇴 때 댓글 자리 남기기는 댓글·답글 삭제 규칙(SOC-01, SOC-02)에, 탈퇴 때 알림 지우기는 알림함(GAME-08)에 의존한다.
- 대상 사용자는 최신 Chrome·Edge·Safari와 모바일 Chrome·Safari를 쓴다고 가정한다 (NF-21).
