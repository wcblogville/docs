## 1. 화면 라우트 `/admin`

| 항목 | 내용 |
|---|---|
| 파일 | `src/app/admin/page.tsx` |
| 접근 | `requireAdmin()`: 로그인하지 않은 사람과 일반 회원은 `notFound()` → 404 화면 (`길을 잃었어요`). 관리자 화면이 있다는 것을 드러내지 않는다 (FR-043, SC-008). **바뀌는 점**: 지금은 비로그인을 `/`로 보낸다 |
| 헤더 | [👑 관리자] 링크는 관리자에게만 (헤더는 town 소유, 지금 그대로) (FR-015) |
| 접근성 | 375px에서 가로 스크롤 없음: 휴대폰 폭에서는 표 대신 행을 쌓은 목록. [삭제] 버튼과 제목·블로그 링크의 누르는 영역 44×44px, 버튼 글자 한 줄 (FR-054, SC-011). **바뀌는 점**: 지금 [삭제](`src/app/admin/delete-button.tsx`)는 `text-sm` 글자만이라 누르는 영역이 작다 |

**통계 카드 5개** (FR-044, 순서대로)

| 카드 | 값 | 바뀌는 점 |
|---|---|---|
| 가입 계정 | `users` 행 수 | - |
| 전체 글 | `posts` 행 수 (공개·비공개 모두) | - |
| 댓글 | `comments`와 `replies`에서 `deleted_at IS NULL`인 행 수의 합 | `replies`는 social 5단계 뒤에 더한다. 그 전에는 `comments`만 |
| 오늘 새 글 | `posts.created_at >= startOfTodayKST` (한국 시간 0시) | - |
| 오늘 출석 | `attendances.date = todayKST()` | - |

`주민 (온보딩 완료)` 카드는 없앤다 (spec Assumption).

**최근 가입 회원** (FR-045): `users.created_at` 최신순 20명.

| 열 | 값 |
|---|---|
| 아이디 (로그인 방식) | `{아이디} ({방식들})`. 방식: `credential` → `아이디`, `kakao` → `카카오`, `naver` → `네이버`, `google` → `Google`. 예: `tester1 (아이디, 카카오)` |
| 닉네임 | `profiles.nickname` (늘 있음. `온보딩 전` 표시는 없앤다) |
| 블로그 | `@{주소}` → `/@{주소}` 링크 |
| 권한 | `👑 관리자` / `회원` |
| 가입 | `formatDateTime(created_at)` |

**최근 글** (FR-046): 최근 30일, 최대 30개, 최신순.

| 열 | 값 |
|---|---|
| 제목 | `/@{주소}/{글ID}` 링크 |
| 작성자 | 블로그 주인 닉네임 |
| 공개 | `공개` / `🔒` |
| 작성 | `formatDateTime(created_at)` |
| (버튼) | [삭제] |

## 2. Server Action `adminDeletePost(postId)`

| 항목 | 내용 |
|---|---|
| 파일 | `src/app/admin/actions.ts`, 버튼 `src/app/admin/delete-button.tsx` |
| 권한 | `requireAdmin()`. 일반 회원·비로그인이 직접 보내면 `notFound()` (404) 이고 아무것도 지우지 않는다 (US5 #3, SC-008). 상태 코드는 구현 전 확인, 기준은 "데이터 변경 0건" |
| 입력 | `postId: number` → `parseId()` (1~2147483647 정수). 통과하지 못하면 아무것도 하지 않는다 |
| 화면 확인 창 | `'{제목}' 글을 삭제할까요?` (FR-047) |
| 처리 | 어느 블로그의 글이든 `posts` 행 삭제 → 그 글의 댓글·답글·공감·태그 연결 CASCADE → `revalidatePath("/", "layout")` |
| 보상 | 이미 지급된 경험치·코인은 회수하지 않는다 (D6) |

처리는 지금 코드 그대로이고, `requireAdmin()` 변경(비로그인도 404)만 영향을 준다. 버튼(`delete-button.tsx`)은 누르는 영역만 44×44px로 넓힌다.

## 3. 명령 `npm run admin:create` (`scripts/create-admin.ts`)

| 항목 | 내용 |
|---|---|
| 입력 | `.env.local`의 `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `DATABASE_URL` (값은 서버에만 둔다. 문서·코드에 쓰지 않는다) (FR-048, NF-01, NF-14) |
| 전제 | `npm run db:migrate`, `npm run db:seed` (기본 캐릭터·초원 아이템) |
| 종료 코드 | 성공 0, 검사 실패·오류 1 |

**검사와 메시지** (운영자 콘솔 메시지)

| 상황 | 메시지 | 바뀌는 점 |
|---|---|---|
| 둘 중 하나가 없음 | `.env.local에 ADMIN_USERNAME, ADMIN_PASSWORD를 적어 주세요` | 그대로 |
| 아이디가 `^[a-z0-9_]{4,20}$`가 아님 (앞뒤 공백 제거·소문자 뒤) | `관리자 아이디는 영문 소문자, 숫자, _ 로 4~20자여야 해요` | 새로 (`users_username_check`, 로그인 규칙과 맞춤) |
| 비밀번호 12자 미만 | `관리자 비밀번호는 12자 이상이어야 해요` | 8자 → 12자 (FR-048) |
| 비밀번호 64자 초과 | `관리자 비밀번호는 64자까지예요` | 새로 (로그인 상한) |
| 비밀번호가 아이디와 같음 | `관리자 비밀번호는 아이디와 달라야 해요` | 새로 ("추측하기 어려운 값"의 최소 확인) |
| 아이템이 없음 | `아이템이 없어요. 먼저 npm run db:seed 를 실행해 주세요` | 그대로 |

**동작** (한 트랜잭션, 여러 번 실행해도 안전)

| 상태 | 처리 |
|---|---|
| 그 아이디의 회원이 없음 | 회원(`role = 'admin'`, ID는 `newAuthId()` 32자) + credential 로그인 수단 + 기본 캐릭터 `char_boy`·초원 + 프로필(닉네임 `관리자`) + 블로그(`notice`, `Blogville 공지사항`, 소개 `마을 소식과 업데이트를 알려드려요`) + 대분류 "공지" |
| 회원이 있음 | `role = 'admin'`으로 맞추고 비밀번호 해시만 갱신. 블로그가 이미 있으면 건너뜀 (US5 #4) |
| 회원·로그인 수단 ID가 32자가 아님 (예전 형식) | ID를 바꾸지 않고 경고와 다시 만드는 방법(`npm run db:reset` 뒤 `npm run admin:create`, 로컬)을 출력 (FR-049, US5 #5) — 지금 구현 그대로 |

- 관리자 계정은 회원가입의 예약어·이름 겹침 검사(FR-010)를 받지 않는다 (spec Assumption). 운영자는 다른 회원이 쓰는 주소·닉네임과 겹치지 않는 아이디를 고른다.
- 출력: `✔ 관리자 계정 준비 완료: {아이디}`. 비밀번호는 출력하지 않는다 (FR-012).
