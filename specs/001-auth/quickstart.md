# Quickstart: 회원 / 인증 (AUTH) 검증

**Spec**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Contracts**: [contracts/](contracts/) | **Date**: 2026-10-07

이 기능이 끝까지 동작하는지 확인하는 실행 순서다. 명령은 코드 저장소 루트에서 실행한다. 구현 코드와 테스트 본문은 여기 쓰지 않는다 (tasks·구현 단계에서 만든다).

- 1단계(가입 통합) 뒤에는 4.1·4.2·4.6과 회귀 e2e를, 8단계 뒤에는 4.3~4.5(탈퇴 제외)·4.7을, 9단계 뒤에는 4.5의 탈퇴까지 돌린다. 단계는 [plan.md 변경 단위 표](plan.md#현재-코드--spec-목표-변경-단위)를 따른다.
- 비밀값(DB 접속 정보, 로그인 비밀키, 소셜 Client Secret, 관리자 비밀번호)은 `.env.local`에만 둔다. 이 문서와 e2e 코드에 값을 적지 않는다.

## 0. 전제

- Node.js 20.9 이상, PostgreSQL (README 안내는 17), 의존성 설치(`npm install`)가 끝난 체크아웃. 이 기능은 새 패키지를 더하지 않는다.
- `.env.local` (`.env.example`을 복사): `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`(로컬은 `http://localhost:3000`), `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `UPLOAD_DIR`, 소셜 키 `GOOGLE_CLIENT_ID`/`_SECRET`, `KAKAO_CLIENT_ID`/`_SECRET`, `NAVER_CLIENT_ID`/`_SECRET`.
  - **바뀐 규칙**: `ADMIN_USERNAME`은 영문 소문자·숫자·`_` 4~20자, `ADMIN_PASSWORD`는 12~64자이고 아이디와 달라야 한다 (FR-048). 지금 값이 짧으면 `npm run admin:create`가 실패한다.
  - 소셜 키는 비워 둔다 (6장 수동 확인 때만 채운다). 키가 없으면 그 서비스 버튼이 꺼진다.
- 마이그레이션 전 점검: [data-model.md 4장 "적용 전 점검"](data-model.md#4-마이그레이션-순서와-데이터-이전)의 조건이 모두 0행인지 본다. 아니면 로컬은 `npm run db:reset` 뒤에 진행한다.

## 1. 준비

```bash
npm run db:migrate     # auth 마이그레이션: 1단계 A1~A3, 8단계 A4~A6
npm run db:seed        # 기본 캐릭터(남자·여자 주민)·초원 등 카탈로그
npm run db:reset       # 로컬 DB만: 회원·글·로그인 실패 기록 비우기 (관리자도 지워짐)
npm run admin:create   # .env.local의 관리자 계정과 /@notice
npm run dev            # 다른 터미널에서 계속 실행 (http://localhost:3000)
```

기대:

- `db:migrate`가 오류 없이 끝나고, 가입 미완료 회원(프로필 없는 회원)이 0명이다.
- `admin:create`가 `✔ 관리자 계정 준비 완료: {아이디}`를 출력한다. **한 번 더 실행**해도 관리자 회원 1명, 주소 `notice` 블로그 1개다 (US5 #4).

## 3. E2E 실행

개발 서버가 떠 있어야 한다. 첫 인자는 스크린샷 폴더다.

```bash
mkdir -p shots
node e2e/auth.mjs shots          # 고침
node e2e/signup.mjs shots        # 새로 (1단계)
node e2e/session.mjs shots       # 새로 (8단계)
node e2e/login-limit.mjs shots   # 새로 (8단계)
node e2e/account.mjs shots       # 새로 (8단계, 탈퇴 부분은 9단계)
```

회귀 확인 (`e2e/helpers.mjs`의 `loginDev`가 바뀌므로 이것에 기대는 시나리오를 다시 돌린다):

```bash
node e2e/blog.mjs shots && node e2e/social.mjs shots && node e2e/visits.mjs shots && node e2e/params.mjs shots
node e2e/write-count.mjs shots && node e2e/attachments.mjs shots && node e2e/farm.mjs shots
node e2e/game.mjs shots && node e2e/decisions.mjs shots && node e2e/mobile.mjs shots
node e2e/nonfunctional.mjs shots
```

- 기대: 가입·로그인 단계에서 실패가 없다 (온보딩 화면을 기다리다 멈추는 곳이 없다).
- 알려진 예외: `e2e/social.mjs`의 "온보딩 전 회원" 준비 블록은 새 구조에서 만들 수 없어 social이 고친다 (plan 의존성). `e2e/game.mjs`·`e2e/decisions.mjs`의 출석·상점·광장 확인은 game·shop·town 변경으로 바뀐다 (공통 맥락 6.3).

### 4.3 `e2e/session.mjs` (새, 8단계)

시간 조건은 DB의 `sessions.expires_at`·`updated_at`을 당겨 만든다.

| # | 실행 | 기대 | 연결 |
|---|---|---|---|
| 1 | [로그인 상태 유지] 없이 로그인 | 세션 쿠키에 만료 없음, `HttpOnly`, `SameSite=Lax` (로컬은 `Secure` 없음). DB `remember_me = false`, `expires_at` ≈ 지금 + 2시간 | FR-019, FR-020, FR-023 |
| 2 | 만료 없는 쿠키를 뺀 새 브라우저 컨텍스트(브라우저를 닫았다 연 것)로 `/write` | `/`로 이동 | US2 #6 |
| 3 | `expires_at`을 지금 + 100분으로 당긴 뒤 회원 화면을 연다 | `expires_at` ≈ 지금 + 2시간으로 다시 늘어남 | FR-020 ("다시 시작") |
| 4 | `expires_at`을 과거로 → 회원 화면 | `/`로 이동 | US2 #6, FR-022, SC-005 |
| 4-2 | 유지 안 함으로 로그인한 회원 화면에서 `GET /api/auth/get-session` 요청이 없는지 본다(`SessionKeeper`를 그리지 않음). 이어서 `dont_remember` 쿠키를 지우고 `GET /api/auth/get-session`을 직접 부른 뒤, DB `updated_at`을 2시간 10분 전으로 당기고 회원 화면을 연다 | `/`로 이동, 그 세션 행 없음 (라이브러리가 `expires_at`을 늘렸어도 마지막 사용 2시간 규칙이 이긴다) | FR-020, SC-005, research R6-4 |
| 5 | [로그인 상태 유지]를 골라 로그인, 만료 없는 쿠키를 뺀 새 컨텍스트로 회원 화면 | 쿠키 만료 ≈ 7일 뒤, `remember_me = true`, 새 컨텍스트에서도 로그인 유지 | US2 #7, FR-021 |

| 7 | 유지 세션 `expires_at`을 과거로 → 회원 화면 | `/`로 이동 | SC-005 |
| 8 | 헤더 [로그아웃] | 확인 없이 `/`로, 헤더 [시작하기], 그 세션 행 삭제, `/write` → `/` | US2 #8, FR-029 |
| 9 | `TESTER`처럼 대문자·앞뒤 공백을 섞은 아이디로 로그인 | 로그인됨 | US2 #2, FR-016 |
| 10 | 아이디나 비밀번호를 비우고 [로그인] | `아이디와 비밀번호를 적어 주세요` | US2 #3 |
| 11 | 로그인 처리 중 버튼 | `들어가는 중...`, 누를 수 없음 | US2 #9, FR-018 |
| 12 | 로그인한 회원의 쿠키를 붙이고 Origin을 다른 사이트로 바꿔 로그아웃·연동 해제·관리자 글 삭제(관리자 쿠키)·탈퇴 Server Action을 보냄 | 성공이 아님, 세션·연동 행·글·회원 그대로 | FR-024, SC-009 |

### 4.4 `e2e/login-limit.mjs` (새, 8단계)

| # | 실행 | 기대 | 연결 |
|---|---|---|---|
| 1 | 새 회원으로 5번 연속 틀린 비밀번호 → 6번째에 맞는 비밀번호 | 1~5번째 `아이디 또는 비밀번호가 맞지 않아요`, 6번째 `로그인을 너무 많이 시도했어요. 5분 뒤에 다시 시도해 주세요`, 로그인 안 됨 | US6 #1, FR-025, SC-006 |
| 2 | DB로 `login_attempts.locked_until`을 과거로 → 맞는 비밀번호 | 로그인됨, 그 아이디의 실패 기록 행 없음 | US6 #2, FR-026 |

## 6. 소셜 수동 확인 (키가 있을 때)

자동 e2e로는 실제 소셜 로그인을 할 수 없다. 키를 발급받은 뒤 한 번 확인하고 결과를 PR에 적는다 (constitution 품질 관문).

**준비 (운영 설정)**

- 각 개발자 센터의 Redirect URI: `http://localhost:3000/api/auth/callback/kakao` (`naver`, `google`도 같은 꼴).
- 카카오 동의 항목: 닉네임·프로필 사진만. 네이버 제공 정보: 이메일을 고르지 않는다. Google: 범위 `openid`, `profile` (FR-035).
- `.env.local`에 키 이름만 채우고 `npm run dev`를 다시 띄운다.
