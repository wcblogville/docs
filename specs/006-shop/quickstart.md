# Quickstart: 상점 / 꾸미기 (SHOP) 검증

이 기능이 끝까지 동작하는지 확인하는 실행 순서와 시나리오다. 명령은 코드 저장소 루트에서 실행한다. 구현 코드는 적지 않고, 무엇을 돌리고 무엇이 나와야 하는지만 적는다. 인터페이스 세부는 [contracts/](contracts/), 표 구조는 [data-model.md](data-model.md)를 본다.

## 0. 준비

**선행 작업**

- auth 단계 1(가입 통합, 온보딩 없애기, `e2e/helpers.mjs`의 `loginDev` 수정)이 `main`에 있어야 새 e2e가 실행마다 새 회원을 만들 수 있다.
- PostgreSQL 15 이상(README 안내는 17), Node.js 20.9 이상, `npm install`을 마친 체크아웃.
- `.env.local`에 `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`가 있어야 한다. 값은 팀 채널로 받고 문서·코드에 적지 않는다. e2e는 `dotenv`로 이 파일을 읽는다.

**구현 전 확인** (research에 "구현 전 확인"으로 남긴 것)

- `node_modules/drizzle-orm`의 node-postgres 마이그레이터가 대기 중인 마이그레이션을 한 트랜잭션으로 실행하는지 (R2). 어느 쪽이든 CHECK를 `type::text`로 쓰면 안전하다.
- `drizzle-kit generate --custom --name=…` 옵션 (데이터 마이그레이션 파일 만들기), Drizzle `real()`·복합 `onConflictDoUpdate` target (R4, R10).
- `node_modules/next/dist/docs/`의 Server Action 인자 직렬화와 `revalidatePath` (R17).

## 1. 마이그레이션 확인 (기존 데이터가 있는 로컬 DB, S-00)

판매 중단 이전이 "보유·장착·코인을 건드리지 않는지"를 보려면 **`db:reset` 전에** 한 번 적용한다.

```bash
npm run db:migrate
npm run db:seed
```

기대 결과 (`npm run db:studio` 또는 `psql`로 확인)

| 확인 | 기대 |
|---|---|
| `items`에서 `type = 'character'`인 행 | 11행 모두 남아 있고 모두 `is_on_sale = false` |
| `items`에서 `is_on_sale = true`인 행 | 22행: avatar 9 · furniture 5 · background 5 · growth 3 (SC-011) |
| `user_items`에서 `quantity <> 1`인 행 | 0행 (기존 행은 모두 1) |
| `profiles.character_item_id`, `blogs.background_item_id` | 적용 전과 같음 (FR-011, SC-010) |
| 회원별 `SUM(point_ledger.coin_delta)` | 적용 전과 같음, `purchase`의 음수를 돌려주는 기록 없음 (SC-010) |
| `npm run db:migrate`를 한 번 더 | 오류 없이 "적용할 것 없음" |

## 4. E2E 실행

새 시나리오 두 개와 영향을 받는 기존 시나리오를 돌린다. 첫 인자는 스크린샷 폴더다.

```bash
node e2e/shop.mjs e2e-shots/shop          # 새: 상점 (실행마다 새 회원, ❌가 있으면 exit 1)
node e2e/closet.mjs e2e-shots/closet      # 새: 꾸미기 (실행마다 새 회원, ❌가 있으면 exit 1)
node e2e/game.mjs e2e-shots/game          # 고침: 잠김 확인이 토끼 → 눈 마을
node e2e/decisions.mjs e2e-shots/decisions  # 고침: GAME-01 확인 방법, SHOP-04 고양이 장착 그대로
node e2e/blog.mjs e2e-shots/blog && node e2e/params.mjs e2e-shots/params   # 범위 밖 숫자 (상점·꾸미기 인자 추가)
node e2e/mobile.mjs e2e-shots/mobile
node e2e/nonfunctional.mjs e2e-shots/nf   # 375px 가로 스크롤 (/shop, /closet 포함)
```

새 e2e의 공통 방식(기존 관례): 파일 맨 위에 확인하는 요구사항 ID와 사용법 주석, `pg` Pool로 코인·레벨·보유를 준비하고 결과 행을 셈, `check(이름, 참거짓)`로 `✅`/`❌`를 모아 출력, 조작 요청과 동시 요청은 `e2e/params.mjs`처럼 진짜 Server Action 요청을 한 번 잡아 인자만 바꿔 다시 보냄. 코인 준비는 `point_ledger`에 직접 기록을 넣고, 레벨 준비는 경험치 기록을 넣는다 (`e2e/decisions.mjs`와 같은 방식). 코인을 "정확히 N"으로 맞출 때는 그날 첫 화면을 연 뒤(game 자동 출석 보상이 들어간 뒤) 원장 합계를 다시 읽어 차이만큼 기록을 넣는다. 그렇지 않으면 출석 보상이 나중에 더해져 "잔액 = 가격" 준비가 어긋난다.

**완료 조건**: 위 명령이 모두 `❌` 없이 끝나고(`process.exit(1)`을 쓰는 새 e2e와 `params.mjs`는 종료 코드 0, 실패해도 종료 코드가 0인 `decisions.mjs`·`mobile.mjs`·`nonfunctional.mjs`는 출력에 `❌`가 없음, `check`가 없는 `game.mjs`는 출력한 버튼 글자가 5.3 기대와 같음), 콘솔·페이지 오류(`collectErrors`)가 없고, 6장의 스크린샷을 눈으로 확인했다. 결과를 PR 설명에 적는다 (CI가 없으므로 작성자가 직접, constitution 품질 관문).
